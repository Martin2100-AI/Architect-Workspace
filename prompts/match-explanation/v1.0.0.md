## Instructions

You are comparing one property against a buyer's stated search criteria for
Keysy's property discovery feed. Your audience is the UI layer that renders the
match explanation to the buyer — not the buyer directly — so return only
structured data, never a conversational sentence.

buyerFilters may have any of these eight fields set (unset ones are null, or []
for features): city, zipCode, priceMin, priceMax, bedrooms, bathrooms,
propertyType, features.

Check each field that IS set in buyerFilters against propertyData using these
exact rules, and record the result as one of these criterion names:

- "city" — matches if propertyData.city equals buyerFilters.city, ignoring
  case. Only checked if buyerFilters.city is set.
- "zipCode" — matches if propertyData.zipCode equals buyerFilters.zipCode.
  Only checked if buyerFilters.zipCode is set.
- "price" — matches if propertyData.price is greater than or equal to
  buyerFilters.priceMin (when set) AND less than or equal to
  buyerFilters.priceMax (when set). Only checked if priceMin or priceMax is
  set; treat it as ONE combined criterion, not two.
- "bedrooms" — matches if propertyData.bedrooms is greater than or equal to
  buyerFilters.bedrooms. Only checked if buyerFilters.bedrooms is set.
- "bathrooms" — matches if propertyData.bathrooms is greater than or equal to
  buyerFilters.bathrooms. Only checked if buyerFilters.bathrooms is set.
- "propertyType" — matches if propertyData.propertyType equals
  buyerFilters.propertyType, ignoring case. Only checked if
  buyerFilters.propertyType is set.
- One criterion per entry in buyerFilters.features, using that feature's exact
  name (e.g. "pool", "no-hoa") — matches if that name appears in
  propertyData.features.

Put the name of every criterion you checked into either matchedCriteria or
unmatchedCriteria — never both, never omit a criterion you checked.

Handle these three situations exactly as described:

- **If information is missing** — propertyData is missing or null for a field
  a checked criterion needs (e.g. propertyData.features is null while the
  buyer asked for "pool"): treat that criterion as unmatched. Never assume a
  missing value satisfies the buyer's request.
- **If the input is ambiguous** — a criterion can't be evaluated at all
  because propertyData has no corresponding concept for it (this should be
  rare given the fixed field list above, but if it happens, do not guess and
  do not include that criterion in either list).
- **If there is nothing to report** — buyerFilters has no fields set at all
  (every field is null or [], meaning the buyer stated no criteria): both
  matchedCriteria and unmatchedCriteria are empty arrays. This is not a
  failure — an unstated criterion cannot be violated.

Once you have both lists, set overallFit using this exact rule, in this exact
order:
1. If unmatchedCriteria is empty, overallFit is "full-match".
2. Otherwise, if "city" or "propertyType" appears in unmatchedCriteria, or
   unmatchedCriteria has 2 or more entries, overallFit is "poor-match".
3. Otherwise, overallFit is "partial-match".

## Input

Buyer's stated criteria:
{{buyerFilters}}

The property being evaluated:
{{propertyData}}

## Output format

Return exactly one JSON object with these three fields, and nothing else — no
preamble, no explanation, no text before or after the JSON:

```
{
  "matchedCriteria": array of strings,
  "unmatchedCriteria": array of strings,
  "overallFit": "full-match" | "partial-match" | "poor-match"
}
```
