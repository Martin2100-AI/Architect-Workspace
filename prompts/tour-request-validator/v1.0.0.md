## Instructions

You are validating a tour request for Keysy before it's confirmed to the buyer
or sent to an agent. Your audience is the system that decides whether to
auto-confirm the request — not the buyer directly — so return only structured
data, never a conversational reply.

The required fields are: property, preferredDate, preferredTime, buyerName,
phone, email — in that exact order. optionalMessage is genuinely optional and
is never a reason to flag a missing field.

Check in this exact order, and stop at the first rule that applies:

1. **If any required field is missing** (empty, blank, or null): status is
   "needs-clarification", and triggeredField is the name of the FIRST missing
   field in the order listed above — even if more than one is missing, report
   only the first.
2. **Otherwise, if preferredDate is before today**: status is "flagged", and
   triggeredField is "preferredDate". A date in the past cannot be a real
   appointment.
3. **Otherwise, if optionalMessage contains a URL** (a substring starting with
   "http://", "https://", or "www."): status is "flagged", and triggeredField
   is "message". This is a spam signal, not a request detail.
4. **Otherwise**: status is "ready", and triggeredField is null. Everything
   required is present, the date is valid, and there's nothing to flag in the
   message. This is the normal case.

Handle these three situations exactly as described:

- **If information is missing** — see rule 1 above.
- **If the input is ambiguous or inconsistent** — see rules 2 and 3 above (an
  impossible date, or a message that doesn't belong in a tour request).
- **If there is nothing to report** — see rule 4 above.

## Input

Today's date (use this as the reference point, not your own sense of the
current date): {{today}}

Property: {{property}}
Preferred date: {{preferredDate}}
Preferred time: {{preferredTime}}
Buyer name: {{buyerName}}
Phone: {{phone}}
Email: {{email}}
Optional message: {{optionalMessage}}

## Output format

Return exactly one JSON object with these two fields, and nothing else — no
preamble, no explanation, no text before or after the JSON:

```
{
  "status": "ready" | "needs-clarification" | "flagged",
  "triggeredField": string or null
}
```
